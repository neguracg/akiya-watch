# 指示書: セッションログからの決定事項抽出（heavy-intake S1）

発注: 2026-09-05 オーケストレータ
目的: 2026-06-13〜2026-09-04 のセッションログ（ユーザー発言＋アシスタント本文のみを抽出済み）から、
「要件・決定・却下・宿題」を構造化して取り出す。後工程（S2統合→S3でSPECへ反映）はこの出力**だけ**を読む。

## 入力
`C:\Claude\30_akiya-watch\_pipeline\log\in\chunk_NN.md`（担当チャンクは起動プロンプトで指定）。
形式: `### [日時] USER|ASSISTANT` のエントリが時系列に並ぶ。USER＝腱さん（PM・発注者）本人の発言。

## 出力（担当チャンクごとに1ファイル・書けた分から保存）
`C:\Claude\30_akiya-watch\_pipeline\log\out\s1_chunk_NN.md`
**開始時にこのファイルが既にあればそのチャンクはスキップ**（冪等）。
1チャンク処理し終えるごとに必ずファイルへ書いてから次へ進む。

### ファイルの章立て（この順・見出し固定）
```
# s1 chunk_NN（期間: 最初の日時 〜 最後の日時）

## A. 腱さんが述べた要件・条件（原文引用＋日時）
- [2026-06-14 10:22] 「…原文の要点（30〜80字で引用）…」 → 何の要件か（1行）

## B. 決定事項（何を・なぜ・日時）
- [日時] 決定: … ／ 理由: … ／ 決めた人: 腱さん|Claude提案→腱さん承認

## C. 却下・保留した案（理由つき）
- [日時] 案: … ／ 却下理由: …

## D. 宿題・約束・未完了（その時点で）
- [日時] … （後で完了した形跡がこのチャンク内にあれば「→ 同チャンク内で完了」と付記）

## E. 固有名・用語（人名は役割だけ。個人が特定される情報は書かない）
- 用語: 意味

## F. 設計判断（方式選択の理由が語られているもの）
- [日時] 方式: … ／ 選んだ理由: … ／ 代替案: …

## G. 腱さんの指摘・不満（Claudeの作業への訂正。今後の作り方に効くもの）
- [日時] 「引用」 → 何が問題だったか
```

## 規律
- **原文にあることだけ書く。** 補完・推測をしない。判断が要る箇所は「（要確認）」を付けて残す
- 日時は必ず付ける（エントリ見出しの日時をそのまま）
- 同じ決定が繰り返し語られていれば1つにまとめ、最初と最後の日時を書く
- 実装の細部（関数名・行番号・CSS値）は書かない。**何を・なぜ**だけ
- ツール出力の数字（件数・サイズ）は書かない（腐る）
- 1チャンクの出力は 80〜200 行。超えそうなら重要度の低いものを落とす（A/B/G を優先）
- 再委任禁止。git操作禁止。出力ファイル以外を書かない
