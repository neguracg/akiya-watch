# 指示書: 既存26アダプタの `<sup>` 分断バグ横展開監査（2026-09-05）

## 背景（機構の言語化）
面積セルが `495m<sup>2</sup>` のように **子タグで数値と単位を分断** している時、
`el.get_text(" ", strip=True)`（区切り文字あり）は `"495m 2"` を返し、`_first_sqm` の
`m2` パターンに一致せず `area_sqm=None` になる。区切りなし（`get_text(strip=True)` ＝
`_numeric_cell_text(el)`）なら `"495m2"` で一致する。坪の併記があるセルは坪換算で偶然
救われる（値は微妙にずれる）。2026-09-05 のキャンプ場土地バッチ5/7/10（e-z／しずなび／
東急リゾート）で発見し、`_numeric_cell_text`（watch.py 1054行付近）へ部品化済み
（commit 1e14e8f, 7f62230, b3eae5e, 073307f）。

**機構語での検索条件**: 「面積（または価格）を `_first_sqm`/`parse_area_sqm`/`parse_price_man`
へ渡す文字列を、区切り文字付き `get_text(" ", strip=True)` で作っている箇所」。
文字列grepでは `tds = [x.get_text(" ", strip=True) ...]` → `specs[...]` → `_first_sqm(specs.get("土地面積"))`
のように**2〜3行離れて**いるので、各アダプタの面積抽出経路を1本ずつ手で辿ること（棚卸しモード）。

## 着手前4問（kaishu-policy）

   集約に乗っていない既存経路を洗い出す作業そのもの。
2. **同種の既存機能**: 下表の26アダプタ（本指示書がその全数リスト）。
3. **引っ越しか**: 否。
4. **過去の類似改修**: `git log --grep=sup` → 073307f（部品化）。BUGLOG/WORKLOGに `<sup>` 分断の
   記録は新規3アダプタ分のみ（既存アダプタは未調査）。

## 絶対ルール
- **urls.yaml のURLは変更しない**。404/405等でも「要確認」として記録するだけ。
- **監査フェーズ（本指示書）では watch.py・urls.yaml・data/・reports/ を一切編集しない**。
  結果は指定の結果ファイルにだけ書く。
- `robots_allowed(url, session)` が False のサイトは **fetchしない**（静的判定のみ・「robots制限のため実測不可」と記録）。
- 1サイトにつき **fetchは1回**（LIFULL は累積202制限があるため特に）。取得HTMLは
  スクラッチパッドに保存し、以後はそのファイルを読む。
- Windows: 子プロセス出力は UTF-8 明示（`$env:PYTHONIOENCODING='utf-8'`）。

## 手順（アダプタごと）
1. **コード静的判定**: watch.py の対象関数を読み、面積を `_first_sqm`/`parse_area_sqm` に渡す
   文字列の作り方を特定し、次のどれかに分類:
   - **A**: `get_text(" ", strip=True)`（区切り付き）で作った文字列を渡している → バグ候補
   - **B**: `get_text(strip=True)` / `_numeric_cell_text` / 正規表現でHTMLから直接 → 安全
   - **C**: カード全文や複数要素の結合など、Aだが単位表記が別経路でも拾える（例: 坪併記）→ 要実データ判定
   - **X**: そもそも面積を抽出していない（一覧に面積が無い等）→ 非該当
   価格（`parse_price_man`）も同じ機構なので、ついでに同様に分類して記録する（修正対象は今回は面積のみ。
   価格側で壊れているのを見つけたら「報告のみ」で表に載せる）。
2. **実URL取得**（A/Cのアダプタは必須。B/Xも「`<sup>`が使われているか」の事実確認のため1サイトは取得）:
   - (a) pwsh: `Invoke-WebRequest -Uri <url> -UseBasicParsing -UserAgent "<watch.pyのHEADERS['User-Agent']と同じ>" -Headers @{'Accept-Language'='ja,en;q=0.9'}` の `StatusCode` を記録
     （例外時は `$_.Exception.Response.StatusCode.value__` を記録）。非ASCII URLは `-Uri` にそのまま渡してよい。
   - (b) python: `watch.fetch(url, session)` でHTML取得（watch.py と同じ経路）。`(status, html)` を記録し、
     HTMLをスクラッチパッドへ保存（`<sid>.html`）。
     ```python
     import sys, importlib.util, requests
     sys.argv=['x']
     spec=importlib.util.spec_from_file_location("w","watch.py"); w=importlib.util.module_from_spec(spec); spec.loader.exec_module(w)
     s=requests.Session()
     ok=w.robots_allowed(url, s)  # False なら fetch しない
     st, html = w.fetch(url, s)
     ```
   - 対象サイトは各アダプタにつき代表1 id（下表）。同一アダプタで複数idがあるものは1つでよい。
3. **HTML構造確認**: アダプタが面積に使うセレクタで要素を取り、その **innerHTML（`str(el)`）を先頭200字**
   記録。`<sup>`/`<sub>`/`<span>`/`<small>` 等が **数値と単位の間**に入っているかを判定
   （`sup` 以外の分断も対象。単位の後ろの装飾タグは分断ではない）。
   面積らしい要素が複数あれば、実際に面積抽出に使われる要素で判定する。
4. **実データ検証**（A/C かつ分断タグあり の場合のみ）:
   - 現行アダプタを保存HTMLで実行し、`area_sqm` が None の件数／全件数と、サンプル3件の値を記録。
   - **修正案を watch.py に書かずに**検証する: 同じHTMLで、分断要素の `get_text(strip=True)` を
     `_first_sqm` に通した値と現行値を並べる（スクラッチのスクリプトで、対象セルを直接取って比較すればよい）。
   - 「現行=None／修正後=数値」または「現行=坪換算の近似値／修正後=㎡表記の正確値」なら **該当（壊れている）**。
     差が無ければ **非該当（偶然救われている・分断なし）** とし理由を書く。
5. 結果ファイルに **1アダプタ1ブロック** で追記（下の書式）。**アダプタごとに書き終えてから次へ進む**
   （途中で落ちても完了分が残るように）。
