## 2. 判定・データの決定

| 日付 | 決定 | なぜ |
|---|---|---|
| 2026-06-13 | 閾値・キーワードは urls.yaml の `filters:` が唯一の定義。コードに書かない | 変更のたびにコードを触らない |
| 2026-06-13 | 除外(exclude)/注意(caution)/本命(interest)の3系統。除外した物件も理由付きでログに残す | 黙って消すと監査できない。借地・定期借地は除外でなく注意へ |
| 2026-06-14 | 重複判定は **正規化所在地＋面積＋価格の完全一致**のみ。所在地不明は統合しない | 誤統合を避ける保守的設計 |
| 2026-06-14 | 「農家住宅」「分家」等は**属人性フラグ**（除外しない） | 譲渡制限の疑いは注意喚起で足りる |
| 2026-06-15 | 「適合」という概念を廃止。価格・面積は既定フィルタとして最初から効かせ、解除できる | 「収集・適合・表示」が混ざって分からない、の指摘 |
| 2026-06-17 | SUUMOのbot対策ページ（極小HTML）を検出したら**前回スナップショットを保持**し「要確認」にする | 抽出0を正規0件と誤認して全件消滅させた事故 |
| 2026-06-19〜20 | fetchに総時間デッドライン（使い捨てスレッド＋join）、1サイト上限、全体ウォールクロック上限、ページャのループ検知 | 7時間超ハング。socket timeoutは総時間を制限しない。ThreadPool案（枯渇）・stream案（実測でハング）は却下 |
| 2026-06-21 | LIFULLは巡回順を全体に分散し土地/中古戸建を交互配置 | IP単位の累積リクエスト数で202になる |
| 2026-06-23 | 非表示・★の単位は**バックエンドのdedupキー**（url+text先頭60字）。近似名寄せへ広げない | 別物件の巻き込み事故を防ぐ |
| 2026-06-24 | 非表示・★は `{bdk, snap}` のスナップショットで保存し、元物件が消滅しても一覧に残す | 「非表示にしたのに5件しかない」バグ |
| 2026-07-25 | 賃貸の「駐車場」は独立種別にして既定非表示（種別フィルタで出せる） | 激安帯が駐車場で埋まり住居が見えない |
| 2026-07-26 | スナップショットに判定済み20項目を保存する | `--rebuild` で判定を再現できず本番を劣化させかけた |
